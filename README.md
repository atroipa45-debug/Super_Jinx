# 3x-ui روی Railway — «جینکس | Super JinX» — خودکارِ کامل

ساخته‌شده برای کانال: **https://t.me/Super_Jinx**

---

## قبل از هر چیز — چند تا حرف صادقانه

من این باندل رو با دقت و بر اساس مستندات و کد واقعی 3x-ui نوشتم، ولی روی یک دیپلوی واقعی Railway تست عملی نکردم (امکان اجرای مستقیم Railway رو ندارم). دو تا قول که نمی‌تونم بدم:

1. **«صد در صد کار کردن» رو نمی‌تونم تضمین کنم.** نسخه‌های پنل گاهی فرمت API رو کمی عوض می‌کنن؛ برای همین این بار به‌جای «امیدوار بودن»، یک سیستم لاگ‌گیری و healthcheck واقعی گذاشتم (پایین توضیح دادم) که اگه چیزی خراب باشه، دقیقاً همون لحظه توی لاگ Railway با ❌ مشخص می‌شه — نه اینکه ساکت خراب بمونه.
2. **پینگ به تنظیمات پنل ربطی نداره.** پینگ صرفاً به فاصله‌ی جغرافیایی شما تا دیتاسنتر Railway بستگی داره (که معمولاً آمریکا/اروپاست). هیچ تنظیمات نرم‌افزاری نمی‌تونه این فاصله‌ی فیزیکی رو عوض کنه؛ اگه پینگ پایین می‌خواید، باید سرور رو به یه ریجن نزدیک‌تر (VPS در کشور نزدیک‌تر) منتقل کنید.

## این نسخه چیکار می‌کنه (خودکار، بدون دخالت شما)

با بالا اومدن کانتینر:
1. یوزر/پسورد/پورت/مسیر پنل رو ثابت می‌کنه.
2. با پنل لاگین می‌کنه.
3. تنظیمات Subscription (Path, Port, Enable, URI) رو از طریق API پنل خودش تنظیم می‌کنه — دیگه لازم نیست دستی برید توی Subscription Settings چیزی بزنید.
4. اینباند VLESS+WebSocket با نام **جینکس | 𝙎𝙪𝙥𝙚𝙧 𝗝𝗶𝗻𝗫** رو می‌سازه (UUID و subId ثابت، تا لینک‌ها بین ری‌استارت‌ها عوض نشن).
5. هر ۶۰ ثانیه یک چرخه‌ی نگهبان اجرا می‌شه که:
   - چک می‌کنه اینباند هنوز هست؛ اگه پاک شده بود، دوباره می‌سازدش.
   - چک می‌کنه تنظیمات ساب دستکاری نشده؛ اگه شده بود، برمی‌گردوندش.
   - یک تست واقعی HTTP به خود سابلینک می‌زنه و نتیجه (۲۰۰ یا خطا) رو با ✅/❌ توی لاگ می‌نویسه.

## دیپلوی

1. همه‌ی فایل‌های این زیپ رو در ریشه‌ی یک ریپازیتوری گیت‌هاب بریزید.
2. Railway → **New Project → Deploy from GitHub repo**.
3. **Settings → Networking → Generate Domain** بزنید — **Target Port: `8080`**.
4. سرویس رو یک‌بار **Restart** کنید (تا متغیر `RAILWAY_PUBLIC_DOMAIN` که تازه ساخته شده، در دسترس بوت‌استرپ قرار بگیره و سابلینک خودش دامنه‌ی درست رو بگیره).

## بعد از بالا اومدن

- پنل: `https://دامنه‌شما.up.railway.app/managepanel/`
- یوزر/پسورد: هرچی در Variables → `PANEL_USER` / `PANEL_PASS` گذاشتید (پیش‌فرض admin / ChangeMe123! — **حتماً عوضش کنید**)
- وقتی وارد پنل بشید، اینباند «Super JinX» و تنظیمات ساب از قبل آماده‌ن.
- سابلینک نهایی همون چیزیه که تب Inbounds → کلاینت → دکمه‌ی Sub نشون می‌ده.

## اگه چیزی کار نکرد

برید تب **Deploy Logs** توی Railway. هر خطی که با ❌ شروع بشه دقیقاً می‌گه کجا مشکل هست (مثلاً «ذخیره‌ی تنظیمات ساب شکست خورد» یا «تست سابلینک جواب ۵۰۲ داد»). همون خط رو کپی کن بفرست، مستقیم می‌ریم سراغ رفعش — دیگه لازم نیست حدس بزنیم.

## متغیرهای قابل تنظیم (Railway → Variables)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PANEL_USER` / `PANEL_PASS` | admin / ChangeMe123! | حتماً عوض کنید |
| `PANEL_PATH` | /managepanel | مسیر ورود به پنل |
| `WS_PATH` | /wspath | مسیر اینباند |
| `SUB_PATH` | /subpath | مسیر سابلینک |
| `WS_PORT` / `SUB_PORT` / `PANEL_PORT` | 10001 / 2096 / 2053 | پورت‌های داخلی |
| `CLIENT_UUID` / `SUBID` | رندوم | اگه می‌خواید لینک هیچ‌وقت عوض نشه، ثابت بدید |
| `INBOUND_REMARK` | جینکس \| Super JinX | اسم اینباند |

برای پایداری کامل بین ری‌دیپلوی‌های کامل (نه فقط ری‌استارت)، یک **Volume** روی `/etc/x-ui` و `/etc/x-ui-bootstrap` وصل کنید.
